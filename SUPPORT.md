# FAULTLINE Support

## Usage questions

After Discussions is enabled, use **Discussions → Q&A** for workbench, oracle, reducer and WebMCP questions that are not confirmed bugs.

## Bugs

Use the structured bug form. Include:

- browser/version,
- exact oracle,
- smallest synthetic HTML/CSS/JS case,
- expected versus observed PASS/FAIL/UNRESOLVED result,
- whether the issue reproduces with the public deployment or current main,
- relevant console output with private data removed.

## Reproducer contributions

Use the failure-case/fixture form for synthetic browser failures that can become public regression cases. Real customer/private source must be reduced/anonymized before submission.

## Security

Potential sandbox, navigation, result-channel, persistence-isolation or WebMCP boundary vulnerabilities must be reported privately using `SECURITY.md`.

## Response expectations

FAULTLINE currently has no paid or guaranteed-response SLA. GitHub is the canonical public support path.
